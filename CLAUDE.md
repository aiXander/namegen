# CLAUDE.md

## Mission

Nameforge: a name generator built on one premise — LLMs are bad at inventing truly novel names (they produce the predictable, internet-average token), so **statistics invent and AI judges**. Character n-gram Markov chains trained on curated word lists — plus a **brief lexicon** (real words for the brief's ideas, which LLMs *retrieve* well) and, when breeding, the previous round's winners — sample thousands of fresh, pronounceable candidates under constraints; a cheap score-only screen and a panel of fast LLM judges find the gems; the user rates a shortlist, and those ratings feed back into the judges as taste examples and into the next round's training data. Python backend (Flask API + Markov engine + AI scoring) with a React/TypeScript GUI. Local-only; nothing is deployed.

## Blast radius

- **Free to run without asking:** both test scripts, the benchmark/profiler, ruff, `npm run build`, starting the dev servers, and small real AI calls (judging ~50 names costs a fraction of a cent) to verify prompt or model changes.
- **Ask first:** anything that would spend more than ~$1 of OpenRouter credit, and bulk rewrites of user data (below).
- **User data — never clobber:** `saved_ratings.json` (the shortlist + the judges' taste examples), `config.yaml` (mutated by the GUI on every change; expect it dirty in git), `word_list_ratings` inside it, `.cache/` (paid-for embeddings and LLM responses).

## Standing debugging priors

- **AI call 404s with "0 endpoints … guardrail/ZDR"** → the model isn't allowed by the OpenRouter account's zero-data-retention setting. Pick another model; don't debug the code.
- **"Reasoning is mandatory for this endpoint"** → handled automatically (retry at `low`); if it surfaces, the fallback in `ai/llm.py` regressed.
- **Generation slow or returns few names** → read the `stats` in the `complete` event / Results summary first: it's usually the novelty filter (`min_edit_distance`) or tight constraints, not the sampler.

## Repo layout

- `markov/` — the engine, bottom-up: `markov_model.py` (weighted n-gram counts → tempered chains + untempered probabilities), `generator.py` (orders 1..N with backoff, `log_likelihood`), `constraint_sampler.py` (constraints integrated *during* sampling; `GenerationConstraints.is_feasible()`), `multi_component_sampler.py` (fixed components + multi-word output), `name_generator.py` (public `NameGenerator` facade + `naturalness()`), `dataset_stats.py` (per-list "Markov health").
- `markov_namegen.py` — CLI entry point and shared helpers: `MarkovNameGenerator` (loads config + word lists, `source_weights()`, lexicon/seed mixing via `extra_sources()`), `nearest_training_word()`, `too_close_to_training()`.
- `api_server.py` — Flask API on :5001: `/api/generate-stream` (SSE: one event per name with naturalness + nearest training word, then generation stats), `/api/ai/judge-stream` (quick screen → panel), `/api/ai/lexicon`, `/api/ai/final-round`, `/api/ai/embed-rank-stream`, `/api/ai/models`, `/api/word-lists`, `/api/config`, `/api/ratings` (names travel in JSON bodies — they can contain spaces). Caches one trained generator keyed by sources + model params + weighting.
- `ai/` — `judge.py` (`NameJudge` screen + panel + final round, prompts), `lexicon.py` (brief lexicon), `embeddings.py` (optional Vibe column, SQLite vector cache), `llm.py` (async OpenRouter wrapper: JSON mode, retries, disk cache, concurrency window), `cost_tracker.py`.
- `react_gui/src/` — `App.tsx` owns config (debounced autosave), ratings and the session (names, verdicts, similarities, final ranking; mirrored to localStorage); tabs `BriefTab` (brief, vibe words, lexicon), `TrainingDataTab` (Sources), `SamplingParametersTab` (with live preview), `AITab` (Judge), `ResultsTab` (keyboard triage), `SavedResultsTab` (Shortlist). All backend calls go through `services/api.ts`; shared helpers in `lib/names.ts`.
- `word_lists/` — 69 curated raw lists, one entry per line; edit these. `word_lists_clean/` — generated by `scripts/clean_word_lists.py` (transliteration, dedup, compound-splitting for English-compound lists only); preferred by both entry points when present (`WORD_LISTS_DIR`). Never edit it by hand.
- `scripts/` — `test_constraints.py`, `test_scoring.py`, `benchmark_sampling.py`, `profile_generation.py`, `time_embeddings.py`, `clean_word_lists.py`.

## Load-bearing rules

1. Constraints are integrated into sampling, never generate-then-filter (that collapses to ~1% success on combined constraints) — see the sampling doc.
2. Temperature reshapes *observed* transitions only; unseen transitions stay at exactly 0 (an epsilon produces unpronounceable names at T>1).
3. A judge failure must surface as an unscored name (`score: None`), never a silent 0.
4. Every judge/embedding model must be routable under the account's ZDR setting — probe new models with one real call before making them a default.
5. Names being judged are excluded from the taste examples sent to the judges (otherwise they parrot the user's rating back).

## Definition of done

- `uv run scripts/test_constraints.py` and `uv run scripts/test_scoring.py` pass; after touching `markov/`, also run `uv run scripts/benchmark_sampling.py` and compare success rates.
- `uv run ruff check .` clean; for GUI changes `CI=true npm run build` in `react_gui/` compiles with zero warnings.
- GUI changes verified in a browser (generate → judge → final round), prompt/model changes verified with a small real judging run.
- Doc pass done (`doc-pass` skill; other agents: `~/.claude/skills/doc-pass/SKILL.md`).

## Cross-cutting invariants

- All generation is lowercase. Constraint strings are lowercased and stripped of stray quote characters (`dequote()`), because users copy the quotes from the GUI's quoted examples.
- A **space in `includes`** means two-word output (`'co ' + ends_with 'a'` → `code noda`); it reroutes to the component sampler, which places a literal space and resets the Markov context per word.
- `config.yaml` is the single source of truth for every setting; the GUI rewrites it whole (the server keeps `word_list_ratings` authoritative). Judge settings live under `llm` (`description`, `keywords`, `guidance`, `judges`, `final_model`, `final_size`, `chunk_size`, `embedding_model`, `available_models`) plus `ai_settings.max_names` (names that get a full verdict; the quick screen picks them). The lexicon and breeding live under `training_data` (`lexicon`, `lexicon_share`, `breed`, `seeds`, `seed_share`).
- All AI calls go through OpenRouter (OpenAI SDK at openrouter.ai) with `OPENROUTER_API_KEY` from the repo-root `.env`; real cost comes from OpenRouter's usage accounting.

## Commands

```bash
make start                            # API + GUI + open browser (scripts/start.sh; reuses running servers, Ctrl-C stops both, NO_OPEN=1 skips the browser)
uv run api_server.py                  # API on :5001 (debug reloader: editing a .py restarts it mid-request)
cd react_gui && npm start             # GUI on :3020 (PORT is pinned in package.json)
uv run markov_namegen.py              # CLI generation from config.yaml, no GUI, no AI
uv run scripts/test_constraints.py    # constraint correctness
uv run scripts/test_scoring.py        # weighting, naturalness, judge aggregation (no network)
uv run scripts/benchmark_sampling.py  # per-attempt success rates (reads config.yaml sources — pin them when comparing)
```
